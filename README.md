# DUBI Web UI

DUBI 内嵌管理界面，使用 **React + TypeScript + Vite**。这是独立源码仓库；构建产物随 DUBI 服务端发布，运行时只需要一个 `dubi` 二进制，不需要 Node.js、Nginx 或另起前端服务。

当前已接入管理员登录、会话恢复与退出，以及集群概览、区域与节点、存储与容量、维护诊断和当前入口的只读管理 API。保留已确认的蓝灰配色、紧凑分组菜单、自定义下拉选择和详情抽屉。租户、访问凭证、备份、监控通知、引擎目录和配置中心也已接入；未开放模块明确显示不可用。

## 目录与构建

推荐并列检出：

```text
dubi-project/
├── dubi/       # Go 服务端
└── webui/      # 本仓库
```

构建环境需要 Node.js 20.19+ 或 22.12+ 的受支持版本、npm，以及 DUBI 所需 Go 工具链。依赖固定在 `package-lock.json`。

只构建前端：

```sh
npm ci --ignore-scripts
npm run build
```

`dist/` 是 HTML、带内容哈希的 JS/CSS 等静态文件。`src/` 是唯一手工维护的前端代码来源，不修改服务端中的生成文件。

完整构建并嵌入服务端，在 `dubi` 仓库执行：

```sh
./scripts/build.sh
# 或显式指定此仓库路径
./scripts/build.sh /path/to/webui
# 交叉编译 Linux 服务端
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 ./scripts/build.sh
```

这会按锁文件安装前端依赖、检查 TypeScript、生成静态文件、同步到服务端嵌入目录，最后生成 `dubi/dubi`。脚本不自动拉取 Git 分支，发布时由构建方选择两个仓库的版本。

## 接入约定

- 同一个 HTTPS Origin 提供页面与 `/api/v1/...`，浏览器用相对路径请求 API，不硬编码节点 IP。
- 根路径 `/` 打开控制台；页面路径使用 `#/...`，刷新保留当前页面。`/assets/...` 只服务实际存在的构建资源，API 和内部 RPC 不回退成 HTML。
- 管理员原始 Token 只用于登录，提交后清空输入，不写入 localStorage、URL 或日志。会话由服务端 Secure、HttpOnly Cookie 管理；CSRF Token 只保留在页面内存。
- 管理 API 使用 `data` / `meta` 包装。身份与登录接口沿用自身契约。参考相邻服务端仓库 `docs/api/management.md`。
- 缺失、不可达、过期、不完整的数据必须真实展示；配置中心管理 API 复核管理员身份和租户模块权限后访问数据。
- `npm run dev` 仅是前端开发预览，未配置 API 代理或证书。完整登录联调使用 DUBI 的真实 HTTPS 入口，不能为了开发关闭 TLS、Origin 或 CSRF 检查。
- 本项目服务器测试和真实联调在 VPS 完成；开发机可编辑、类型检查、构建。不要在开发机启动 DUBI 测试集群。

正式 UI 继续复用 `src/api.ts` 的请求约定和既有身份边界，再按功能拆分页面。无需为了这层管理界面引入 SSR、React Server Components 或单独部署的 Node 服务。

### Stitch 参考的取舍

保留现有深蓝灰侧栏和浅灰内容区。参考 `stitch_dubi_webui` 的信息层级、区域内节点视图、紧凑表格、搜索筛选和详情抽屉，补齐从概览到具体节点的查看路径。

Stitch 中的固定三副本、Volume 绑定租户、节点超时自动隔离、账号密码 / SSO、多租户通用凭据、虚构延迟与吞吐指标不作为产品能力继承。仓库备份等后续页面按实际接口逐步设计，不直接移植设计图中的操作按钮。

## 已接入的只读管理页面

| 页面 | 查询接口（`/api/v1/admin`） |
| --- | --- |
| 集群概览 | `/cluster` |
| 区域与节点 | `/regions`、`/nodes`、`/regions/{id}/nodes` |
| 节点详情 | `/nodes/{id}` |
| 存储与容量、Volume 详情 | `/volumes`、`/nodes/{id}/volumes`、`/nodes/{id}/volumes/{volume_id}` |
| 监控与诊断、节点维护详情 | `/maintenance`、`/nodes/{id}/maintenance` |
| 右上角账户菜单 → 当前入口信息 | `/gateway` |

节点、Volume 与维护列表默认每页 20 条，可选 50、100，按服务端游标提供上一页、下一页。节点名称查询为精确匹配；更改筛选或页大小后从第一页读取。区域卡片只展示摘要；节点详情按需读取 Volume 和维护数据。存储页使用集群级 `/volumes` 接口，列顺序为 Volume / 路径、节点 / 区域、容量 / 使用、写入隔离、状态、操作；点击 Volume 打开独立的 Volume 抽屉。容量卡片使用集群文件系统汇总，避免直接累加同一文件系统上的多个 Volume。节点列表也将状态放在操作前一列。

Volume 筛选默认全部状态。节点选择与区域联动：未选区域时禁用节点下拉，不查询全群节点；选择区域后每批加载 50 个节点，按需加载更多，使用 NodeID 提交筛选。切换或清除区域会清空节点选择，所有筛选变化重置 Volume 页码。下拉支持键盘导航，到最后一项按向下键可加载下一批节点；加载失败可重试。

当前由顶栏刷新按钮手动刷新；详情抽屉有独立刷新按钮。不定时发起后台请求。每个查询都有加载、空结果、部分观测和失败状态；503 保留旧结果并明确标记，403/404 清除旧结果，401 清除当前会话 UI。切换查询会取消旧请求，并通过请求序号防止迟到响应覆盖新结果。缺失容量或维护数量展示未知，不能用 0 代替。

## VPS 验证

`scripts/read-only-ui-checks.jsx` 与 `scripts/read-only-ui-bootstrap.mjs` 是仅供独立演示 VPS 的测试入口。前半段在 jsdom 中运行 React，通过正常校验的 HTTPS、Cookie 与 Origin 连接真实三节点演示服务；后半段注入明确的测试响应，覆盖分页、空结果、响应乱序、503 重试、部分观测、403 与 401。测试不模拟真实浏览器布局或完整 Cookie 安全策略；TLS、Cookie 属性和 CSRF 由服务端 HTTPS 验收脚本另行验证。原始 Token 只在 VPS 从私有凭证文件读取，不写入报告。

在独立 VPS 测试目录复制 `src/` 和 `scripts/`，使用 Node.js 22，安装固定测试依赖：

```sh
npm install --no-audit --no-fund --ignore-scripts react@19.3.1 react-dom@19.3.1 jsdom@26.1.0 esbuild@0.25.12
./node_modules/.bin/esbuild scripts/read-only-ui-checks.jsx --bundle --platform=node --format=esm --packages=external --loader:.css=empty --define:import.meta.env.DEV=false --jsx=automatic --outfile=scripts/readonly-checks.bundle.mjs
node scripts/read-only-ui-bootstrap.mjs
```

测试中的演示地址和凭证路径明确限定为既有 TT01 演示环境。结果保存在运行目录的 `ui-check-results.json`。不要在开发机运行此验收，也不要在生产集群执行测试注入或演示凭证流程。


### 租户管理设计预览

本地打开 `/?preview=1&page=tenant` 可直接查看租户管理设计。包含租户概览、标识搜索、凭证状态筛选、分页、详情抽屉和创建表单。访问状态按有效凭证派生，不引入后端尚未定义的租户启停状态；创建仅保存在当前组件内存中，离开页面或刷新后恢复演示数据。未接入真实租户管理 API，不向 VPS 部署此预览。

租户预览增加名称、模块允许列表和整体逻辑存储配额。标识用于 API/SDK，创建后不可修改；名称用于展示、可修改。列表优先展示名称，标识放在第二行；创建与设置表单可选择模块并配置 GiB 配额，默认不限额。模块示例为配置中心/缓存，实际接入时必须以集群可用模块为准，新模块不自动授权。配额拟按所有模块的租户逻辑数据总量计量，不含副本、Pack 和集群备份仓库占用；超过限额拟保留读取/删除、限制新增数据，不自动删数据。所有字段和规则仍为本地交互设计，未改 Root Tenant 模型或鉴权、存储配额执行。

### 访问与凭证设计预览

本地访问 `/?preview=1&page=credentials`，无需登录。页面包含管理、租户、监控凭证分类，名称/标识/租户搜索，状态与即将到期筛选，分页，详情抽屉，创建和撤销确认。创建表单按类型展示固定权限边界，租户凭证选择所属租户；Token 只在创建后的界面显示，预览生成的 `preview_not_valid_` 内容不能用于真实访问。弹窗头尾固定，中间表单独立滚动。

这是前端交互设计：名称和跨类型凭证列表等字段尚未据此新增服务端 API。数据只保存在当前页面内存，刷新后恢复，不读取真实凭证、不连接 VPS，也不写入浏览器持久存储。`CredentialsPreview.tsx` 仅在开发模式按需加载，不进入正式构建。正式登录后的“访问与凭证”暂保持未开放状态，待页面设计确认后再接入接口。

### 仓库与备份设计预览

本地访问 `/?preview=1&page=backup`，无需登录。页面上方以区域风格卡片展示备份仓库，下方固定展示备份记录。点击卡片筛选对应仓库，再次点击或选择全部仓库解除筛选；卡片支持默认仓库切换、设置和详情。备份记录包含搜索、状态/仓库筛选、分页、节点执行进度与详情抽屉，立即备份优先使用当前选中的仓库。添加仓库默认使用文件目录，也可选择 S3，按独立字段填写 Endpoint、Bucket、Prefix、Region 与访问凭据。同一文件路径按各节点本地目录解释，无需共享目录。

备份按集群整体展示，增量复用对象，每次已完成且封存的备份对应独立恢复点。立即备份只创建内存中的待执行记录，不伪造完成结果；恢复准备只展示全新空集群所需的步骤，不执行恢复。仓库可访问性和任务统计使用设计样例，未据此新增管理 API；新增或修改仓库后显示未检查，不模拟真实连通性测试。

`BackupPreview.tsx` 仅在开发模式按需加载，不进入正式构建。所有改动仅保存在当前页面内存，离开页面或刷新后重置。S3 表单请仅填写示例凭据，保存时丢弃密钥值，不写入浏览器持久存储、不连接存储服务或 VPS。正式入口待设计确认后接入后端。

## 访问与凭证、仓库与备份

正式页面已接入管理 API：凭证列表、筛选、签发、一次性 Token、撤销确认和详情；仓库卡片、新建/设置、默认仓库；集群备份创建、记录分页、真实节点进度与恢复准备。仓库默认 file，支持 S3 的独立配置参数和加密凭据。页面不再使用预览数据作为真实接口的回退。恢复准备读取已封存恢复点元数据，实际写入新空集群由恢复工具执行，不在当前集群触发覆盖恢复。

### 监控与诊断 UI 预览

开发服务启动后访问 `/?preview=1&page=monitoring`，无需登录。沿用控制台样式，提供区域/节点联动、时间范围、健康摘要、吞吐/延迟趋势、节点监控、后台任务、诊断记录、详情抽屉和采集接入说明。列表状态在操作列左侧，新诊断记录排在最前。正常/异常场景、筛选、分页与运行检查均可交互。

此阶段仅设计 UI：指标、任务历史与检查结果均为本地示例，尚未接入真实采集或诊断 API。无观测显示未知而非零。预览组件通过 DEV 条件加载，生产构建不包含这些样例，也不会替换现有线上维护页面。

监控与诊断页面已接入真实管理 API，支持区域/节点筛选、业务 HTTP 吞吐与延迟趋势、CPU/RSS、后台维护观测和手动诊断。趋势每 10 秒采样，在节点内存中保留 6 小时；最近 50 次诊断记录由集群持久保存。接口与采样口径见 [监控与诊断 API](../dubi/docs/api/monitoring.md)。

### 控制台地址

控制台使用 Hash 路由，以 URL 作为当前页面的来源，支持刷新恢复、直接链接及浏览器前进/后退。未登录访问指定地址时，登录后保留目标页面。

- `#/cluster/overview`：集群概览
- `#/cluster/nodes`：区域与节点
- `#/storage/volumes`：存储与容量
- `#/tenants`：租户与配额
- `#/access/credentials`：访问凭证
- `#/access/accounts`：管理账号
- `#/backups`：仓库与备份
- `#/monitoring`：监控与诊断
- `#/notifications`：消息与通知
- `#/gateway`：当前入口
- `#/engines-modules`：全局引擎与模块管理
- `#/modules/config`、`#/modules/cache`：按租户管理的业务数据页面

无效路径回到概览；URL 不保存 Token、密码及表单内容。路由不替代服务端授权，尚未开放的模块保持原有提示。列表筛选、分页和临时抽屉仍属于页面内部状态。


### 引擎与模块界面预览

本地入口：`/?preview=1#/engines-modules`。侧栏分为“核心”和“业务数据”，全局“引擎与模块”入口归入核心。

- 上方引擎卡片、下方模块卡片，不用 Tabs 切换；卡片显示名称、说明、状态、能力、关联关系和基本指标。
- 详情使用右侧抽屉，展示标识、接入情况、能力、关联组件、运行指标和配置。关联项可打开对应详情，支持遮罩点击和 Escape 关闭。
- 预览以四种引擎、八种模块展示布局；运行指标、租户数量均为样例，开发中或未接入项目不填充虚假零值。
- 预览支持编辑展示名称与说明、保存和取消，仅保存在组件内存中。当前真实的 State 大小限制仍是内置常量，不提供可修改的假配置；未来只对后端明确声明可编辑的配置展示表单。

### 业务数据与统一租户栏（界面预览）

`src/components/Toast.tsx` 提供全局 `toast.success / error / warning / info(message)`，由入口文件挂载唯一的 `ToastViewport`。

- 页面顶部居中滑入，不占布局空间，不增加遮罩，不抢焦点；详情抽屉和编辑弹窗打开时仍可见、可关闭。
- 成功与普通提示停留 4.5 秒，提醒停留 6.5 秒；错误保留到手动关闭。鼠标悬停、键盘焦点停留或页面隐藏时暂停自动消失。
- 同时只展示最新一条，重复操作重置停留时间；页面路由变化时清除旧提示，避免把旧租户的反馈带到新页面。
- 已替换配置预览、引擎模块预览，以及租户、账号、凭证、仓库与备份页面原有的操作成功条。字段校验、带重试入口的加载错误仍留在原位置；持久集群事件仍进入“消息与通知”。
- 提供成功、错误、提醒、普通四种配色，支持窄屏与减少动态效果设置。新页面统一复用此组件，不再新增角落 Toast 或挤动列表的成功横条。
